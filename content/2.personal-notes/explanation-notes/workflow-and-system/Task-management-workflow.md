# 說明

記錄 `1. Task Management.md` 這則任務管理筆記目前的架構、設計理由，以及還沒解決的部分，供之後回顧或調整時參考。

# 整體架構：Plan → Do → Check（Act 待補）

[[Task Management]] 分三段，分別對應規劃、執行、紀錄：

## 一、規劃任務（Plan）

週目標表格，欄位：

- **工作量**（大/中/小）：卡片盒筆記＝大、考古題＝中、英文筆記＝小，只用來判斷這週排的量會不會偏重，不算進達標統計。
- **可用天數**：預設每週 7 天，0（整天不可用，如考試/出差）／0.5（部分佔用）／1（正常）三檔相加；遇到已知會佔用一整天的事，先從對應週扣。目的是讓目標數字反映實際可用產能（密度＝目標／可用天數），而不是固定死的數字。
- **文獻回顧次數**（原「卡片盒筆記」目標，已改名）：卡片盒筆記的產出量不是能直接控制的變因（讀完文獻有沒有洞見值得寫是不確定的），硬性規定張數會逼出湊數的卡片，違背卡片盒筆記「一張卡一個真正想法」的精神。改成用「回顧文獻/靈感筆記的次數」當目標（這是可控的行為），卡片盒筆記的實際產出量只記錄、不設目標。

## 二、追蹤任務（Do）

分兩條線，因為節奏不同：

- **主任務**：用 Fancy Kanban 外掛的 `fancy-kanban` code block 直接嵌在筆記裡，兩張卡（英文學習筆記／考古題筆記），三階段（未開始/進行中/已完成），可拖曳。每天開始前要手動把卡片撥回「未開始」，沒有自動重置機制。
- **其他雜事**：連結到 `[[To do]]`（Obsidian Kanban 外掛看板），放不定期的雜項待辦。刻意不嵌入畫面而是用連結，因為 Obsidian Kanban 外掛的看板嵌入到其他筆記時會失去互動性（拖曳失效），是外掛本身的已知限制。

## 三、任務紀錄（Check 的資料來源）

嵌入 `monthly tasks calendar bases.base`，裡面有三個 view：

1. **本月任務紀錄**（月曆）：依各筆記的 `date` 屬性畫在月曆上，內建上一頁/下一頁可翻到任何月份。
2. **本月統計**（表格）：篩選「這個月」範圍，依類型分組計數，算出這個月各類型完成幾篇。
3. **歷史統計（依月份）**：不限時間範圍，依月份分組（新到舊），要查任何一個月做了什麼時打開這個 view 往下滾即可；沒有嵌入到 `1. Task Management.md`（那邊只放常看的月曆＋本月統計），需要查歷史時才單獨開這個 base 檔案。

# `date` 欄位語意的釐清（重要）

這次調整前，`date` 欄位在系統原始設計裡（見 [[Workflow-system-overview|工作流系統說明]]）是「排程欄位」：填哪天，那則筆記就會出現在該日的每日完成事項筆記 dataview 清單裡。考古題筆記原本也是這樣用（`date` ＝下次預計複習時間，`最近作答日期` ＝上次實際作答日）。

為了讓「任務紀錄」的月曆／統計能同時比較三種筆記類型「這個月實際完成了什麼」，把 `date` 的語意統一成「完成/記錄日期」，但這跟考古題筆記需要「同時知道上次做了沒、下次何時該做」的排程需求衝突（同一個欄位不能同時代表過去跟未來）。最後決定：

# 卡片盒筆記的 `date` 補齊

卡片盒筆記原本完全沒有 `date` 屬性，已幫既有 24 篇筆記用檔案建立時間回填（例如 `Use.md` → `2026-07-21`），模板也同步加上這個欄位（留空，之後手動填）。用檔案建立時間回填是用系統時間去推測「這篇是哪天寫的」，不是使用者認定的日期，如果之後發現特定筆記的日期不準，可以手動修正。

# Fancy Kanban 語法備忘

`fancy-kanban` code block 的設定曾經因為語法寫錯而報錯（`Columns field "status" is not defined in fields`），排查後在外掛本機的 `main.js` 原始碼裡確認：

- 看板分欄依據的欄位名稱**預設是 `status`**，除非用 `columns: <欄位名>` 明確指定成別的名稱。
- 目前存檔格式版本是 `version: 3`（不是網路文件範例常見的 `version: 2`）。
- `lanes:` 是另外的「второй軸（swimlane）」設定，不需要跟 `columns` 用同一個欄位。

若之後看板又跳出類似錯誤，可以直接查看 `.obsidian/plugins/fancy-kanban/main.js` 裡的 `parseConfig` 函式確認正確語法，比查網路文件準確。
